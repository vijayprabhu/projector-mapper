# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Projector Mapper is a browser-based projection-mapping tool: place, warp, crop and spin images,
videos, shapes and text onto physical surfaces, drive a projector live, or export a PNG / looping
video for the projector's own media player. User-facing docs are in `README.md`.

## Branching workflow (required)

`main` is the default branch and is what GitHub Pages serves
(https://vijayprabhu.github.io/projector-mapper/), so every push to `main` goes live.

For every requested change:
1. Create a feature branch from the latest `origin/main`, named `feature/<short-description>`
   (or `fix/<short-description>` for bug fixes).
2. Commit the work there and push the branch.
3. Summarise the change and ask the user to confirm.
4. Only after the user explicitly confirms, merge the branch into `main` and push `main`.
   Never commit or push directly to `main` without that confirmation.

## Functional Architecture diagram (required on every feature update)

`docs/functional-architecture.svg` is the Functional Architecture diagram. It is generated by
`docs/generate_architecture.py` (plain Python 3, no dependencies).

For every feature or fix branch that adds, removes or changes functionality:
1. Update the blocks, bullet lines and arrows in `docs/generate_architecture.py` so the diagram
   matches the new behaviour (new UI controls, services, export paths, storage, external systems).
2. Regenerate it with `python3 docs/generate_architecture.py`.
3. Render the SVG (for example with Playwright) and check that no text overlaps, runs out of its
   box or is crossed by an arrow.
4. Commit the updated script and SVG on the same branch as the feature.

If a change really has no architectural impact (such as a copy tweak or a style fix), say so in
the summary rather than leaving the diagram out of date without explanation.

## Commands

There is no build, lint or test tooling, and no `package.json`. The app is three static files.

- Run: `python3 -m http.server 8000`, then open http://localhost:8000 (or open `index.html` directly).
- Regenerate the architecture diagram: `python3 docs/generate_architecture.py`.
- Test: drive the served app with Playwright (Chromium). Playwright is not part of the repo;
  install it in a scratch directory. On this machine `~/.npm` has permission problems, so use a
  local cache:
  ```sh
  export npm_config_cache=$PWD/.npmcache PLAYWRIGHT_BROWSERS_PATH=$PWD/.browsers
  npm init -y && npm i playwright && npx playwright install chromium
  ```
  Useful checks: drive the UI through `[data-cmd=...]`, `[data-prop=...]` and `[data-act=...]`
  selectors, read `.layer` element styles, and catch `pageerror`. Test exports with
  `page.waitForEvent('download')`. A fresh browser context has an empty project, so add a layer
  first. Media can be fed in with `setInputFiles('#fileInput', ...)`.

## Constraints

- Plain HTML, CSS and JS: no dependencies, no build step, no ES modules. It must keep working when
  `index.html` is opened from disk (file://).
- Target browsers are Chrome and Edge (exports need WebGL2 and MediaRecorder).

## Architecture

All logic is in one IIFE in `js/app.js`, organised into banner-commented sections.

**Layer model.** Every layer has a base size `w × h` and four output-space `corners`
(TL, TR, BR, BL). It is drawn at its base size and mapped onto the corners with a CSS `matrix3d`
homography (`Geo.homography`). Move, resize, rotate, flip and corner-warp all edit only `corners`,
which is why every layer type can be perspective-warped. Layer types are `image`, `video`
(media stored by `mediaId`), `shape` (SVG generated by `shapeSVG`) and `text`. Optional per-layer
effects:
- `crop` (`{x, y, w, h}` as 0–1 of the source, `shape: 'rect' | 'circle'`, `mode`): image and video
  only. `setCrop` re-maps `corners` through the old homography and rescales `w`/`h`, so the kept
  area stays put on the wall.
- `spin` (rpm) and `spinCcw`: the phase comes from the wall clock (`Date.now`), so the editor and the
  output window stay in step. Content rotates about the crop's centre.

**State and history.** `project` is the single source of truth. Mutate it, then call `commit()`.
That pushes a JSON snapshot onto the undo stack, schedules the IndexedDB autosave and runs
`renderAll()`. During drags, only `renderStage()` runs (the fast path, with no panel re-render), and
`commit()` runs on pointer-up. `restore()` reloads from a snapshot, so all layer state must be
plain JSON.

**Rendering.** `Renderer` syncs `project` into a stage element by diffing layers into `.layer`
elements. It caches by `contentKey` (rebuild the content element) and `styleKey` (crop and spin
styles). The same class drives both the editor `#stage` and the **output window**, a
`window.open` popup whose document and **inline `<style>` are written in `openOutput()`**. Any CSS
that layers need (for example the `.layer.cropped` and `.layer.spinning` clipping, or the
`pm-spin` keyframes) must be added to both `css/style.css` and that inline style block.
`drawOverlay()` draws the selection handles separately, on `#overlay`.

**Export pipeline (must mirror DOM rendering).** `prepareLayers()` turns each visible layer into
a drawable source (an image, a fresh video element, or a rasterised shape or text canvas).
`layerFrame()` applies crop, circle clipping and spin on a 2D canvas. `createWarper()` does the
perspective warp in WebGL2 with an inverse-homography fragment shader. `composeFrame()` composites
the layers with opacity and blend modes. PNG export calls it once. Video export calls it every
frame into `captureStream` + `MediaRecorder` (MP4 if supported, else WebM), in real time. When you
add a visual layer feature, implement it in both the DOM renderer and `layerFrame`/`composeFrame`,
and compare an exported PNG with the editor.

**Persistence.** IndexedDB `projector-mapper` has two stores: `kv` (key `project`: the committed
JSON) and `media` (blobs keyed by `mediaId`). `media` (a Map) holds object URLs for the session.
`gcMedia()` deletes blobs that are no longer referenced, found by regex-scanning the committed,
undo and redo JSON for `"mediaId":"..."`, so keep that key name and format. Save / Open project
writes and reads one JSON file `{ app, project, media }` with the media as data URLs. Loading
merges onto `defaultProject()`, so new project-level fields need defaults there. New layer fields
need defaults in `baseLayer()` and tolerant reads (for example `+L.spin || 0`), because older saved
projects won't have them.

**UI wiring.** Toolbar buttons use `data-cmd` (dispatched by `run()`). Property inputs in the side
panel use `data-prop`, plus `data-num`, `data-bool` or `data-bool-sel` for type coercion in
`readProp`. Panel buttons use `data-act` (handled in the `#props` click handler or `ACTIONS`). The
panel HTML is rebuilt by `renderProps()` on every `renderAll()`. Keyboard shortcuts are in the
single `keydown` handler, which ignores keys while typing in inputs or while the crop dialog is open.
